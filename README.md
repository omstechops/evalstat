# evalstat

Statistical validity tooling for LLM and agent evaluations.

`evalstat` is not an eval runner. Run your evals with whatever you already use
(Promptfoo, Braintrust, a notebook), then hand the per-example scores to
`evalstat` to answer the questions those tools leave open:

- How many examples does this comparison actually need?
- Is the gap between model A and model B distinguishable from noise?
- Across 12 prompt variants and 8 metrics, is the winner a winner or an artifact?
- Does the LLM judge agree with human labels well enough to be trusted?
- Does the average hide a subgroup where the system collapses?

## Status

Pre-alpha. One public function, `paired_bootstrap()`, with 32 tests. Each
function ships together with tests built on cases whose answers are known
independently of this code.

## Why: clustered evaluation sets

Existing eval tooling assumes examples are independent. Real eval sets usually
violate that: questions drawn from the same document, sessions from the same
user, utterances from the same recording or speaker. Treating clustered items as
independent inflates the effective sample size and reports confidence intervals
that are too narrow.

**How much too narrow is measurable.** 300 simulated datasets, 40 clusters of 3
items, intra-cluster correlation ρ = 0.2, nominal 95% intervals on a paired mean
difference. Monte Carlo standard error is about 1.5 points.

| Interval method | Row-level resampling (what standard tools do) | `cluster=` resampling |
| --- | --- | --- |
| percentile | 0.887 | **0.927** |
| basic | 0.890 | **0.933** |
| bca | 0.883 | **0.923** |

A tool that resamples rows reports a 95% interval that covers 88.7% of the time.
That gap is what this library exists for.

Read the second column honestly too: clustering recovers most of the shortfall
but not all of it. At 40 clusters the interval still covers about 93%, because
the cluster bootstrap is consistent in the *number of clusters* and forty is not
many. `paired_bootstrap()` warns below 25 clusters, and the warning says which
direction the error runs. If you need a number to quote, quote the one you
measured, not the one you asked for.

The table is regenerated by
`pytest -m slow tests/test_bootstrap.py::test_cluster_resampling_restores_coverage`.
It sets the default interval method: at this cluster count BCa's corrections buy
nothing that survives the noise, so the default is `percentile`, the method with
the fewest estimated quantities. If the measurement changes, the default can.

## Usage

```python
import numpy as np
from evalstat import paired_bootstrap

# 40 documents, 3 questions drawn from each; system B scored against system A
# on the same 120 items.
cluster = np.repeat(np.arange(40), 3)
score_b = ...  # shape (120,)
score_a = ...  # shape (120,)

result = paired_bootstrap(score_b, score_a, cluster=cluster, rng=20260908)

print(result.estimate)  # mean paired difference, positive favours B
print(result.ci_low, result.ci_high)
print(result.n_clusters, result.seed)
```

The sign convention is `x - y`: positive favours the first argument. Pass
`y=None` when you already hold differences — preference data recorded as -1, 0,
+1 arrives that way — and pass your own `statistic` for anything other than the
mean:

```python
# Share of non-tied items favouring B, resampled by document.
def preference_rate(d):
    decided = np.count_nonzero(d != 0)
    return np.count_nonzero(d > 0) / decided if decided else float("nan")


result = paired_bootstrap(
    preference, cluster=cluster, statistic=preference_rate, rng=20260908
)
```

`statistic` receives the vector of differences, not `x` and `y` separately.
Quantities of the form `statistic(x) - statistic(y)` need different resampling
logic and are deliberately out of scope.

Every call records the seed it ran from, including calls that were given none,
so a result can be reproduced after the fact rather than only in advance.

`paired_bootstrap()` documents its assumptions and the conditions under which
each fails; `help(paired_bootstrap)` is the short version.
